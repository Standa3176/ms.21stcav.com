<objective>
Change WHEN the ops app creates a Bitrix deal for a Woo order: only once the order is paid (D-01), with no CRM writes at all for never-paid orders (D-02), and rework the old D-10 race guard (which assumed order.created always creates) into a per-order lock. Add three cutover-safety guards discovered during planning: (1) SHADOW-* ids from shadow mode never poison bitrix_entity_map (the D-11 shadow run would otherwise leave map rows that break every push after the flip), (2) an optional create-floor so plugin-era orders are never re-created as duplicates on their next order.updated after the flip, (3) a webhook-source allowlist so the clone shops (keep./sonny. — they share the code and possibly the HMAC secret, and their order ids collide with live ids) cannot create live deals.

Purpose: D-01/D-02 stop CRM noise from failed/abandoned orders (order 185265 got two deals). The guards make D-10/D-11 safe to execute.
Output: OrderPaidGate + ShadowId support classes, reworked PushOrderToBitrixJob create path, HandleOrderReceived source guard, 3 config keys, tests.
</objective>

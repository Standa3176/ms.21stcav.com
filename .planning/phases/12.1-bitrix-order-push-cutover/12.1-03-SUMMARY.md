# Phase 12.1 Plan 03: Product rows, Cost and Predicted Margin Summary

A newly created order deal now gets product rows (plus a shipping row) with TAX_RATE derived per line from the Woo tax (D-16), and Cost / Predicted Margin computed from stored supplier buy_price, blanked-and-flagged when any line is uncosted, written only to the discovered pipeline codes, with a required-field rejection classified as its own alerting failure.

## Behaviour
- **Create** (inside the 12.1-01 lock): `dealAdd` payload gets Cost/PM merged (schema-whitelisted); then the map row is persisted (real ids only), `dealProductRowsSet(int dealId, rows)` runs, and `line_items_hash` is stored after the rows call succeeds. Rows are skipped when the order has no positive-quantity lines.
- **Adopted deal**: baseline hash only; no rows, no Cost/PM.
- **Shadow** (`SHADOW-` id): `dealProductRowsSet(0, rows)` is called (SyncDiff with the same correlation id as the `crm.deal.add` diff, which already carries the Cost/PM keys); no map row.
- **Update**: hash equal -> nothing; hash differs -> rows re-set + `dealUpdate` with recomputed Cost/PM (both `''` if incomplete); hash null on a non-push map (legacy/adopted) -> baseline only.
- **D-06**: any line with no resolvable buy_price (unknown, null, <= 0, or empty SKU) -> both fields omitted on create, blanked on update; `crm.deal.cost_incomplete` integration event with `woo_order_id` and `missing_skus`.
- **D-07**: values only go to `CrmPipelineSetting.deal_cost_field / deal_predicted_margin_field`; null codes -> nothing written; a code equal to UF_CRM_1610623973323 is never sent and logs `crm.deal.forbidden_field_skipped`.
- **D-09**: if `crm.deal.add` raises BitrixPermanentException matching `/required|обязател/iu` while Cost/PM were blanked, suggestion `crm_push_failed` sub_kind `required_field_blank` (message names the missing SKUs and says do not write 0); job fails fast (existing `failed()` alerts ops). With complete financials the sub_kind stays `permanent_validation`.
- Money type: `money` schema descriptor -> `80.50|GBP` (order currency); otherwise plain `69.50`.

## Decisions / deviations

1. **Migration timestamp** `2026_10_27_130000` instead of the planned `110000` (orchestrator override; sorts after 12.1-02's `120000`). Independent of the pipeline columns.
2. **Recovery rule for a failed rows call (added)**: the map row is persisted right after `dealAdd` with a NULL `line_items_hash` and the hash is set only once rows succeed. On the update path a NULL hash on a `created_via=push` map is treated as "changed" (re-sets rows), while NULL on any other map (legacy/adopted) just gets a baseline. Without this, a transient rows failure would make the retry adopt the deal and skip its rows forever.
3. **D-16 applied** as instructed: TAX_RATE per line / shipping, snapped to 0/5/20 within 0.5pp, otherwise rounded integer; PRICE always carries the charged amount so rows reconcile.
4. **Orders with no product lines** (e.g. a bare quote-request): financials treated as incomplete without a `cost_incomplete` event (no SKUs to name); nothing written on create. If such an order's deal is rejected for a required field the D-09 message reads "(no product lines)".
5. **Optional trailing `handle()` params** (`?OrderProductRowBuilder, ?OrderDealFinancials, ?OrderLineCostLookup`) resolved via `app()` when null so existing 6-arg test calls still work.
6. Existing `mockBitrixClientForPush()` schema fixture gained `UF_CRM_COST` (money), `UF_CRM_PM` (double) and `UF_CRM_1610623973323`.

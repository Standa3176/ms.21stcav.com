<objective>
Make the D-10 adoption step and the D-11 shadow run safe and complete. Planning found two cutover-breaking gaps in existing code: (1) shadow mode returns SHADOW-{uuid} ids that EntityDeduper persists into bitrix_entity_map for contacts/companies (and adopt-legacy skips any existing deal row, shadow or not) — after the flip those rows make every push fail or skip; (2) adopt-legacy reads `_wc_bitrix24_deal_id` from Woo REST meta_data, but CONTEXT records that the plugin stores it in wp_postmeta, not HPOS meta, so REST may return nothing and adoption would silently map zero orders — combined with D-01 (paid order.updated now creates), every in-flight plugin order would get a duplicate deal.

Purpose: D-10 adoption must actually map plugin deals; D-12 rollback/gap fill relies on the same machinery.
Output: hardened EntityDeduper, BackfillOrdersChunkJob, and a CSV adoption source on the existing command.
</objective>

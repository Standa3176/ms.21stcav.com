# 260912-f8x — Brand rules usable, and special (non-feed) trade costs

**Branch:** `quick/260912-trade-cost-ui`
**Asked for:** "Are brand rules option and input of special (non feed) pricing like platinum and Logi etc on the app (for trade only)"

## The problem

Two separate things, both real, both measured.

**1. Brand rules existed but were unusable.** Only 3 `PricingRule` rows exist in
production, all `default_tier` — no brand or category rule anywhere. Taxonomy
therefore cannot affect pricing at all today. The reason is on the form:
`brand_id` is a WooCommerce term id held as a plain nullable bigint with no
foreign key and no local brands table (D-06 deferred), so the field was a bare
numeric input. Writing a rule for Neat meant already knowing Neat's term id,
typing it, and hoping. Nothing on screen confirmed the number, and the index
table showed a bare integer, so a later reader could not tell which brand a
rule applied to.

**2. The feed cost is not the cost we pay.** The daily supplier feed quotes
SILVER-level Yealink while the business buys at platinum — measured at ~11%
better over 70 SKUs matched by hand on 2026-09-10 (median +10.9%, bimodal: 41
of 70 at 11.1–11.2%). A two-month Logitech arrangement is absent from the feed
entirely. Trade pricing computed off the fed cost therefore gives away the
better buying, and the cost floor bites far earlier than it should: modelling
showed 12% better cost takes trade coverage from 78% to 99.9% and the median
trade discount from 10.2% to 20.9%.

## What was built

### `TradeCostAdjustment` — trade-only cost overrides

Rows are read **only** by `TradeStorefrontPricer`. `products.buy_price` keeps
the feed value untouched, so retail pricing, the health check and the
divergence scan all carry on reading one unchanged column. The better buying is
spent on trade customers rather than given away at retail, which is what the
operator asked for.

- `app/Domain/TradePricing/Filament/Resources/TradeCostAdjustmentResource.php`
  (+ 3 Pages) — `$navigationSort = 115`, group Settings, beside
  CustomerGroupResource (110). Scope and value are UI-only `dehydrated(false)`
  radios; `normalise()` guarantees exactly one column of each pair survives a
  save, because the resolver prefers `absolute_cost` and a stale
  `adjustment_pct` left behind would sit there looking authoritative and doing
  nothing.
- An "In force today" column distinct from "Active": the first is what the
  pricer actually sees, the second is the operator's switch. They differ the
  moment a dated deal lapses, and that difference is the thing worth showing.

### `trade:import-costs` — load a whole price list

The August Yealink list is 120 rows. Typing 70 matches by hand is how a wrong
cost reaches a customer, and a fresh list arrives every month.

Matching is the part that had to be learned from the real file. Midwich prefix
Yealink SKUs with `YEA`, and their `Manu Code` column is the MPN with an
internal id glued on after `**`:

    MidwichSku       Manu Code                  Trade
    YEAA24           A24**1303161               773
    YEAMB65PRO       MB65PRO-A02**1203670       2103

So each row is tried three ways against `products.sku`: manufacturer code split
on `**`, the supplier SKU as given, and the supplier SKU minus its prefix. That
combination is what got 70 of 109 by hand. A row matching nothing is reported,
never guessed at. **Dry-run is the default**; `--apply` writes.

### Brand picker

`app/Domain/Products/Support/BrandOptions.php` — id → name from
`TaxonomyResolver::allBrands()`, cached 1h, **fails soft to `[]`**. An operator
editing a margin must not be blocked by a taxonomy lookup, and the numeric id
still works when Woo is unreachable. Wired into both `PricingRuleResource`
(form and table) and the new resource.

## Decisions worth recording

**`DB::transaction()` had to go.** The `DB` facade is fenced as the `WpDirectDb`
layer and TradePricing is denied it — the SYNC-04 posture, guarded by 14
deptrac tests. Taking the connection off the model
(`TradeCostAdjustment::query()->getConnection()->transaction(...)`) keeps the
transaction without crossing the boundary.

**`{--split-on=**}` is a trap.** A trailing `*` in a Laravel signature makes the
option an ARRAY, so the `(string)` cast threw "Array to string conversion". The
default lives in a class constant instead, with a comment saying why.

**An architecture guard was changed deliberately.**
`PricingRuleResourceAdditiveInvariantTest` pinned the literal
`TextInput::make('brand_id')`. Its stated intent is *"Phase 3 form fields — must
stay"*, and that intent still holds: the field is present and still named
`brand_id`. Only the widget changed. Both it and
`PricingRuleResourceCustomerGroupFieldTest` now pin `Select::make('brand_id')`,
with the reasoning written into the test.

**A row that makes trade cost MORE than the feed is ignored** by the resolver —
three Yealink lines came back at −23%, almost certainly SKU homonyms
(`RCH80`, `CM50`, `CS10-D` remain suspect and unloaded).

## Tests

`tests/Feature/TradePricing/TradeImportCostsCommandTest.php` (12) —
dry-run writes nothing, all three match routes, unmatched rows reported,
re-import replaces rather than stacks, dates and reason carried through, zero
and blank prices skipped, `£1,234.56` parsed, Excel's UTF-8 BOM survived,
missing column and missing file both fail loudly.

Options go in as an **array**, never a command string: `tempnam()` returns a
Windows path and `artisan()`'s string form treats the separators as escapes —
all 12 failed on a garbled `--file` while the command ran perfectly from a
shell.

## Not done — operator decisions, not code

- Loading the 70 Yealink platinum costs. The importer is ready; the numbers are
  a commercial decision, and it is still unconfirmed whether platinum is an
  invoice price or a retrospective rebate. If it is a rebate, pricing trade off
  it sells below actual invoiced cost.
- Brand rule values. Measured positions: Yealink 19.7% median headroom / 14%
  unwinnable, Poly 16.4% / 38%, Logitech 8.4% / 45%, Neat no competitor data.
- Whether to cap the maximum trade discount — some products currently reach
  50%+ off (`YEAMBFSLIFT` at 54%).
- `trade:sync` is still not wired into the daily push and there is no nightly
  reconcile, so trade prices will drift from cost changes until it is.

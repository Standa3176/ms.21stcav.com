# 260914-j0x — Icecat as the grounding source for generated content

**Branch:** `quick/260914-icecat-grounding`
**Trigger:** the 25-SKU B-Tech pilot produced filler copy. Tracing *why* led
somewhere much better than a prompt fix.

## The chain

1. The run announced `No supplier description/spec column found — grounding on
   title + identifiers only.`
2. `supplier_products` has **fourteen columns and no prose**: sku, title,
   manufacturer, mpn, stock, price, rrp, ean, plus sync metadata. So
   `detectDetailColumns()` returns `[]` for every supplier, permanently. That
   message was not a one-off.
3. `IcecatClient` **already fetched the whole product record** and discarded
   everything but image URLs.
4. But Icecat was switched off — `is_active = NO` since **2026-05-24 11:15**.

## Why it was off, and why that is the real bug

`testConnection()` probed ONE hardcoded GTIN — `0711719709695`, a Sony
accessory. Sony is brand-restricted on an Open Icecat account, so Icecat
replied:

> To access Full Icecat content, an app_key is required.

The auth-detection regex was `/access|denied|unauthor|...|app_key|api token|.../i`
— which matches that sentence on **both** `access` and `app_key`. A tier notice
about one product was reported as an account failure, and the integration was
disabled the same morning. **113 days dormant.**

Measured on 2026-09-14, with the stored username alone and no token:

    Icecat coverage: 21 of 30 random published products (70%)

    Samsung NP944XGK   6,042 chars, 19 spec groups
    BenQ 9H.S46TB      4,462 chars, 15
    Yealink A50-010    3,133 chars, 11
    LG 75UN640S        2,603 chars, 12
    Epson V11H740041   1,929 chars, 19
    Barco R9861711     1,778 chars, 14
    LINDY 48098          910 chars,  7

Covered: Philips, Epson, Samsung, Poly, Barco, iiyama, Chief, Yealink, SMART,
LINDY, Neomounts, StarTech, ViewSonic, BenQ, LG. Brand-restricted: Logitech,
Neat, Panasonic, Belkin, Avocor, Huddly.

Notably **LINDY is covered** — the 842-SKU brand previously dismissed as too
thin to be worth listing.

## Changes

**`IcecatClient::fetchProductFacts()`** — returns
`{description, features}` or null. GTIN first, then Brand+ProductCode, matching
`fetchImageUrls()`. `extractDescription()` walks LongDesc →
LongSummaryDescription → ShortSummaryDescription → MiddleDesc, because products
carry different subsets (LH85WMBWLGCXEN has 0 description characters but 11 spec
groups). `extractFeatures()` flattens FeaturesGroups to name => value, capped at
60 — a spec table, not a datasheet dump. Returns null when both are empty rather
than handing the model an empty shell and implying it was grounded.

**`GenerateProductDraftsCommand`** — calls it per SKU and adds
`icecat_description` / `icecat_specifications` to `$facts`. The 260913-trd
grounding floor now treats Icecat content as grounding, so a bare part number is
fine to generate from *if Icecat describes the product*.

**`testConnection()`** — probes several GTINs (first a Barco ClickShare CX-30,
verified Open Icecat on this account) and returns OK as soon as one yields data.
Brand-restriction and Full-Icecat tier messages are explicitly classified as NOT
auth failures. `access` and `app_key` are gone from the auth pattern.

## Deliberately NOT done

The `app_key` / `api_token` / `content_token` naming mismatch is real —
`credentials()` reads all three but `query()` only ever sends `app_key`, and the
stored payload has the other two. It is also **irrelevant**: the account returns
full data with no token at all. Fixing a mapping that changes nothing would be
noise; noted here so the next reader does not re-derive it.

## Tests

`tests/Feature/ProductAutoCreate/IcecatGroundingTest.php` — 9 tests over the
extraction shapes and, most importantly, that a brand restriction can never
again be read as an auth failure.

## Operator steps after deploy

1. `/admin/integration-credentials` → Icecat → **Test** (now passes) → activate.
2. Re-run the pilot, ~50p:

       php artisan products:draft-from-suggestions --brands=B-Tech --limit=25 \
         --source-images --no-confirm

   Expect `icecat NNNN chars, NN spec(s)` lines, and copy citing real
   specifications instead of "designed to complement compatible solutions".

Worth re-testing the image path too — Icecat images are authoritative, so the
web-search + Claude-vision validation that currently drives the 13p/SKU cost may
largely fall away.
